# 26 — QA (Quality Gate)

> Parents: `requirements.md` §16 (self-critique checkpoint), §17 (definition of done), `design-principles.md` (Do-Not list, decision test, credibility model), `source-traceability.md`, `content-inventory.md`, `specs/02-content-strategy.md`, `specs/19-design-system.md`, `specs/20-responsive-system.md`, `specs/22-accessibility.md`, `specs/23-performance.md`, `specs/24-seo.md`, `specs/25-content-integrity.md`.
>
> **Mandate:** this is the **pre-implementation** *and* **pre-ship quality gate**. Nothing is "done" until every gate here passes. It consolidates the self-critique, content-integrity, responsive, accessibility, performance, SEO, functional, cross-browser, and "does it still look AI-generated?" checks into actionable, thresholded checklists. Sign-off = every gate PASS (or a recorded, justified waiver). Buildable/runnable without further strategic decisions.

---

## 1. Purpose & targets

**Purpose.** Guarantee the shipped site is faithful to source, strategically sharp, accessible, fast, responsive, functionally sound, and *does not read as an AI template* — before implementation begins (spec review) and before launch (build review).

**Two checkpoints:**
- **Gate A — Pre-implementation (spec review):** run §2 (self-critique) and §3 (integrity) against the specs + content/data files. Recorded here per `requirements.md` §16. **Stop for approval before code** (`requirements.md` §17).
- **Gate B — Pre-ship (build review):** run §3–§9 against the built site. All must PASS.

**Global pass thresholds (roll-up):**
- Self-critique (§2): **10/10 answerable "yes."**
- Integrity (§3): **zero** prohibited fabrications; counts exact.
- Responsive (§4): mobile-quality checklist passes at 320/375/390/414 + verified at 768/1024/1280/1440.
- Accessibility (§5): axe 0 serious/critical; Lighthouse a11y ≥ 95; keyboard/SR/reduced-motion/400% all pass (`specs/22`).
- Performance (§6): Lighthouse Perf ≥ 90; CWV within `specs/23` budgets.
- Functional (§7): zero dead links, zero console errors, every control has a real action.
- Cross-browser (§8): pass on the full matrix.
- AI-slop audit (§9): **zero** Do-Not violations.

## 3. Content-integrity review (`specs/25` §8, `source-traceability.md`, `content-inventory.md`)

### 3.4 Data-file governance (`specs/25` §7)

## 5. Accessibility QA (align `specs/22`)

- [ ] **axe-core: 0 serious + 0 critical** on every route at **320 / 768 / 1280** (moderate triaged to zero-or-justified).
- [ ] **Lighthouse Accessibility ≥ 95** on every route.
- [ ] **Keyboard-only** (mouse unplugged): skip link works; logical focus order; all interactions operable (nav dropdowns, mobile menu, accordions, tabs, panels, drawers, modal, Explorer, region selector, forms); visible focus ring (2px accent, 2px offset) everywhere; no unintended trap; intended traps (mobile menu/drawer/modal) escapable with Esc; sticky header never obscures focus (2.4.11).
- [ ] **Screen reader** (NVDA+Firefox, VoiceOver+Safari; TalkBack spot on mobile Home + GeoModule): name/role/state announced for every control; disclosure open/close + Explorer result changes announced; no orphaned/duplicated content; map country data reachable as a list.
- [ ] **Reduced motion** (OS setting on): all transforms/scroll-reveal/drawer-slide/chevron/arrow-nudge become instant; shape unchanged; no autoplay/parallax.
- [ ] **Contrast:** per-usage report using `specs/19` tokens — body ≥ 4.5:1, non-text UI ≥ 3:1; captions/accent-text explicitly verified; `ink-300` never carries meaning.
- [ ] **One `<h1>` per page**; contiguous heading outline (HeadingsMap/axe); mono eyebrows are not headings.
- [ ] **Don't-rely-on-color:** every active/selected/error/map state has a second cue (underline/border/marker/`aria-pressed`/`aria-current`/count).
- [ ] **Forms:** labels above (never placeholder-as-label); required in label text; errors `aria-invalid`+`aria-describedby`+summary+focus move; success `role=status`; autocomplete set; no redundant entry; no cognitive CAPTCHA.
- [ ] Skip link, `<html lang="en">`, landmark set (one header/main/footer), no `div onClick`.

**Method/tools:** `@axe-core/playwright` per route/width; `eslint-plugin-jsx-a11y` in CI; manual keyboard + SR passes (`specs/22` §14); color-blind simulation; 400% zoom.

## 6. Performance QA (align `specs/23`)

- [ ] **Lighthouse mobile per route:** Performance ≥ 90, Best Practices ≥ 95 (SEO ≥ 95 §... /a11y ≥ 95 §5).
- [ ] **CWV within budgets:** LCP ≤ 2.0 s, CLS ≤ 0.02, INP ≤ 150 ms (mobile) — lab + field (`web-vitals`).
- [ ] **JS budgets (§`specs/23` 2.1):** shell ≤ 70 KB, per-route initial ≤ 40 KB, total initial ≤ 110 KB; Explorer/maps/`motion`/lucide within caps — enforced by CI bundle gate.
- [ ] **Total transfer ≤ 350 KB** per initial route (Home ≤ 250 KB); ≤ 30 requests; ≤ 3 render-blocking; Brotli + immutable caching.
- [ ] **Code-splitting verified:** Explorer/GeoModule/EcosystemMap/IndustryGrid/ProcessDiagram/Drawer/Modal lazy and **absent from Home's waterfall**; prefetch-on-intent works.
- [ ] **Fonts:** self-hosted Latin-subset woff2, `font-display: swap`, ≤ 80 KB critical, two critical faces preloaded, no CLS from swap.
- [ ] **No banned tech in any bundle:** zero WebGL/Three.js/tile-map/globe/particle/Lottie/large-video/chart-lib; zero third-party runtime requests by default; every dependency justified in `specs/23` §4.
- [ ] **Prerendered HTML** for all primary routes (text LCP from HTML); throttled (Slow 4G + 4× CPU) interaction pass has no long task > 200 ms.

### 7.6 Console/network hygiene
- [ ] **Zero console errors/warnings** on load and interaction across all routes; no 404s in the network panel; no unhandled promise rejections; no hydration mismatch warnings.

**Method/tools:** link-checker crawl; manual route/back/forward/refresh/deep-link pass; Explorer state test (share URL in fresh tab); form validation cases (empty, invalid email, valid); DevTools console/network watch per route.

## 9. Final "does it still look AI-generated?" audit (`design-principles.md` Do-Not)

Zero tolerance — any hit is blocking.

**AI-slop aesthetics — must be ABSENT:**
- [ ] No glowing purple/blue gradients; palette holds near-monochrome warm paper/ink + single terracotta accent (`specs/19` §1.1).
- [ ] No abstract "AI brains," robots, humanoids, glowing spheres.
- [ ] No floating particles / data streams / matrix rain.
- [ ] No excessive glassmorphism/neon; no gratuitous 3D/WebGL décor.
- [ ] No endless rounded cards; no every-section-in-a-card (hairlines carry structure; radius minimal — `specs/19` §1.5).
- [ ] No meaningless animated dashboards / fake charts.
- [ ] No generic "AI-powered future / unlock the power of AI" copy (`specs/02` §2).

**Content anti-patterns — must be ABSENT:**
- [ ] No walls of text / PDF-verbatim dumps; no repeated info across sections.
- [ ] No unnecessary/per-persona/per-industry page sprawl.
- [ ] No decorative buttons / fake "Learn more" going nowhere; no dead-end nav; no disconnected splash screen.

**Integrity anti-patterns — must be ABSENT:** (cross-ref §3) no fabricated clients/logos/testimonials/case studies; no invented stats/metrics/revenue/headcount; no fake awards/certs/partnerships/years; no offices beyond Nairobi; no "deployed" track-record claims.

**Quality anti-patterns — must be ABSENT:** no desktop-only/afterthought responsive; no perf-hurting heavy effects; no interaction-for-novelty; no impressive-but-meaningless elements.

**Positive credibility confirmations (must be PRESENT):**
- [ ] Typography does the heavy lifting; whitespace is structural; hairline rules over boxes.
- [ ] Every diagram encodes a real relationship (spine, ecosystem, four-region geography, process, Explorer).
- [ ] Life Sciences visibly deeper; four pillars read as a connected engine from a question.
- [ ] Reads as a serious African consultancy that *obviously* knows Life Sciences, African markets, and applied AI (credibility model, `design-principles.md`).

**Decision test (apply to any lingering element):** helps understanding/engagement? least visible content that communicates? would a serious consultancy's clients respect it? honest/source-supported? works at 320 as at 1440? — any "no" → fix/remove.
